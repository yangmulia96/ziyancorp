## 1. Telegram channel 404 via curl but bot-object works
**Symptom:** getChat/sendMessage to -1004373452633 returns 404 via raw curl, yet the bot reads messages from that channel and context.bot.send_message(chat_id=..., text=...) succeeds.

**Root cause:** python-telegram-bot library carries an auth context that raw shell curl does not. Raw curl from this host = 404; bot object = OK.

**Action:**
- Do NOT conclude "bot lacks access" from a curl 404. Test via the bot object first.
- In distributor.py, always post to channel with await context.bot.send_message(chat_id=ch, text=caption) — never requests.post curl.
- Accurate channel ID comes from msg.forward_origin.chat.id (PTB 22.6), not from an ID-bot or guessed link.

**Channel facts:** Celine Aurel arsip = -1004373452633 (verified via forward_origin). Bot reads it but raw curl 404 is expected/irrelevant.

**Client:** client_secret.json (Desktop app, project_id: ziyancorp, redirect http://localhost).

**Re-auth command (run from bot dir, background — it opens a consent URL):**
env -u PYTHONPATH ./venv/Scripts/python.exe oauth_channel_check.py --client client_secret.json --token token_celine.json --expected-channel UC0h3xyafx6P6J_CjpzhpSeg
- If browser does not auto-open, copy the printed accounts.google.com/o/oauth2/auth?... URL, open in Bos browser, pick the Celine owner Google Account, authorize. Script captures the redirect and prints PREFLIGHT_OK.
- On success it writes token_celine.json.

**Test upload (private, safe):**

Expect UPLOAD_OK video_id=... + CHANNEL_ID=UC0h3xyafx6P6J_CjpzhpSeg.

- ziyan_credentials/youtube_token_celineaurel.json (old) = 401 expired. Use token_celine.json.
